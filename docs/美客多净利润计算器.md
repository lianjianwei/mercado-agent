# 美客多净利润计算器

> 本文档整理自参考实现 [`mercado-calculadora/index.html`](../../mercado-calculadora/index.html)(美客多核价计算器)。
> 用于说明 **净收益(Net Proceeds)** 的计算逻辑,是净利润功能的本地计算依据,不依赖 AI。
> 整理日期:2026-08-29

---

## 1. 背景与目标

美客多(Mercado Libre)平台发布商品时,**只要求卖家填写一个名为「净收益(Net Proceeds)」的参数**,平台会在此基础上自动叠加佣金、运费等,生成买家看到的发布价。

因此我们的最终目标是:**根据商品成本、重量尺寸、汇率和卖家的目标利润率等参数,算出应该填写的净收益是多少**。

与之配套的衍生输出(平台发布价、佣金、利润、实际利润率)用于展示和校验。

---

## 2. 输入参数

### 2.1 商品输入(每个 SKU 一个)

| 参数 | 单位 | 说明 |
|---|---|---|
| 货源价格(采购成本) | CNY | 人民币 |
| 重量 | g | 包装后实际毛重 |
| 尺寸(长 × 宽 × 高) | cm | 包装后外廓尺寸,用于计算体积重 |

### 2.2 配置参数(全局设置,卖家自定义)

| 参数 | 说明 |
|---|---|
| 目标利润率 | 数字,如 `20` 表示 20% |
| 利润率口径 | 二选一:`模式一(利润 ÷ 净收益)` 或 `模式二(利润 ÷ 平台发布价)` |
| 佣金 | 美客多按产品类型收佣,两类各设一个百分比,如经典 `12%`、铂金 `20%` |
| 贴单打包费 | 每单打包/货代成本,CNY |

### 2.3 汇率数据(USD 为基准)

需要 USD 兑以下货币的汇率:

| 货币 | 用途 |
|---|---|
| CNY(人民币) | 成本/打包费折算、利润显示 |
| MXN(墨西哥比索) | 墨西哥站售价换算 |
| BRL(巴西雷亚尔) | 巴西站售价换算 |
| ARS(阿根廷比索) | 阿根廷站售价换算 |

> 注:运费阶梯表三站齐全(墨西哥 MX、巴西 BR、阿根廷 AR),数据来源与口径见 [§6 站点运费阶梯表](#6-站点运费阶梯表)。

## 3. 计算步骤

记符号:

- `cost` = 货源价格(CNY)
- `packing` = 贴单打包费(CNY)
- `baseCny = cost + packing` —— 人民币总基础成本
- `weight` = 毛重(g),`L / W / H` = 长宽高(cm)
- `r_cny` = USD→CNY 汇率,`r_local` = USD→站点货币汇率(MXN / BRL / ARS)
- `target` = 目标利润率(0.2 表示 20%)
- `comm` = 佣金率(0.12 / 0.20)
- `net` = 净收益(USD) ← **最终目标输出**

### 步骤 1:计算计费重(Billable Weight)

毛重、体积重均以 **kg** 计:

```
actual  = weight / 1000              // 毛重
volume  = L × W × H / 6000           // 体积重(尺寸用 cm,除以 6000)
```

判定规则(与平台一致):

```
if actual < 0.5:     billable = actual          // 毛重 < 500g,始终按毛重,不比较体积重
else:                billable = max(actual, volume)  // 毛重 ≥ 500g,毛重与体积重取较大值
```

### 步骤 2:确定运费档位与运费(USD)

平台按「计费重」落在运费阶梯表的某一档;每一档同时给出两个价:

```
档位 = [ 最小kg, 最大kg, 高售价运费USD, 低售价运费USD ]
```

- **高售价列**:买家展示价 ≥ 站点阈值(墨西哥 `299 MXN`,巴西 `79 BRL`)
- **低售价列**:买家展示价 < 站点阈值

阈值判断依赖最终售价,而售价又依赖运费,存在**循环依赖**。解法(参考实现的做法):

1. 用低售价运费 `ship_low` 求一个中间售价 `belowPrice = (net + ship_low) / (1 - comm)`;
2. 若 `belowPrice × r_local ≥ 阈值`,说明会走「高售价列」,运费取 `ship_high`,否则取 `ship_low`。

### 步骤 3:平台发布价

```
price      = (net + ship) / (1 - comm)      // 买家展示价,USD
priceLocal = price × r_local                 // 站点本地货币
```

### 步骤 4:佣金

```
commission = price × comm                    // USD
```

### 步骤 5:利润(人民币 / 美元)

```
profitCny = net × r_cny - baseCny
profitUsd = profitCny / r_cny
```

### 步骤 6:实际利润率(展示用)

```
模式一:margin = profitCny / (net × r_cny) × 100
模式二:margin = profitCny / (price × r_cny) × 100
```

### 步骤 7(核心):反推净收益

已知目标利润率,解出 `net`。记 `shipping` 为步骤 2 确定的运费(高或低)。

**模式一(利润 ÷ 净收益)**

利润对净收益的占比达到目标:

```
net × r_cny - baseCny = target × net × r_cny
```

解得:

```
net = baseCny / ( r_cny × (1 - target) )
```

> 关键性质:**模式一下,net 与佣金、运费完全无关**,只取决于成本、汇率和目标利润率,一步解出。

**模式二(利润 ÷ 平台发布价)**

利润对发布价(折算成人民币)的占比达到目标:

```
net × r_cny - baseCny = target × price × r_cny
```

代入 `price = (net + shipping) / (1 - comm)`,解得:

```
                       baseCny / r_cny  +  target × shipping / (1 - comm)
net  =  -----------------------------------------------------------------
                       1  -  target / (1 - comm)
```

> 模式二依赖 `shipping`,而 `shipping` 由阈值(步骤 2)决定。参考实现采用**两步求解**:
> 先用低售价运费 `ship_low` 求解 `net` → 代入算 `price` → 若 `price × r_local ≥ 阈值` 则改用 `ship_high` 重新求解。
> 高运费只会把价格推得更高,不会使结论翻转,故两步即可收敛,无需迭代。

## 4. 工作示例(参考实现默认值)

以墨西哥站默认输入校验逻辑:

```
cost=14.90, packing=2.50, weight=320g, L×W×H=0×0×0
r_cny=7.18, r_local(MXN)=17.35, comm=20%, target=20%, 模式二
```

1. **计费重**:`actual=0.32kg < 0.5` → `billable=0.32kg`(毛重)
2. **运费档位**:0.32kg 落在 `[0.3, 0.4]` → 高 `6.31` / 低 `3.16` USD
3. **两步求解(模式二)**:
   - 用 `ship_low=3.16`:
     `net = (17.40/7.18 + 0.20×3.16/0.8) / (1 - 0.20/0.8) ≈ 4.28 USD`
   - 反推售价:`price = (4.28 + 3.16)/0.8 ≈ 9.31 USD ≈ 161 MXN < 299`
   - 落在低售价列,结论成立 → **净收益 = 4.28 USD**
4. **发布价**:`(4.28+3.16)/0.8 ≈ 9.30 USD ≈ 161 MXN`
5. **佣金**:`9.31 × 20% ≈ 1.86 USD`
6. **利润**:`4.28×7.18 - 17.40 ≈ 13.33 CNY ≈ 1.86 USD`
7. **实际利润率(模式二)**:`13.33 / (9.31×7.18) ≈ 19.9% ≈ 目标 20%` ✓

## 5. 两个口径的对比

| | 模式一(利润 ÷ 净收益) | 模式二(利润 ÷ 发布价) |
|---|---|---|
| 分母 | 到手净收益(人民币) | 买家发布价(人民币) |
| 是否依赖佣金/运费 | **否**,一步解出 | 是,需按阈值两步求解 |
| 适用直觉 | 「这一单我赚到手净收益的 X%」 | 「我的报价本身有 X% 利润空间」 |
| 同一目标下净收益 | 更小 | 更大(发布价含运费和佣金) |

> 同一商品、同一目标利润率,**模式二算出的净收益一定大于模式一**,
> 因为模式二的分母(发布价)包含了运费和佣金部分,需要更高的净收益来凑足目标占比。

## 7. 待确认事项

1. **佣金与产品类型的映射**:经典/铂金两类佣金由用户自定义,需要确认每个商品如何判断所属类型(人工选择还是从妙手数据带过来)。
2. **汇率数据来源**:参考实现用 `https://open.er-api.com/v6/latest/USD` 免费接口,mercado-agent 是否沿用该源、如何缓存/离线兜底。
3. **运费是「预估」**:参考实现的运费是内置阶梯表的核价预估,并非平台实时账单,正式上架前需按卖家后台实际运费复核。是否保留同样的提示。
